# Инвест-дайджест для сайта на Tilda

Агент раз в сутки собирает 28 RSS-лент, чистит и дедуплицирует материалы, раскладывает по 26 темам и кладёт два JSON в `docs/`. GitHub Actions публикует `docs/` на GitHub Pages, а блок T123 на Тильде читает JSON через `fetch` и рисует карточки.

```
28 RSS ──► scripts/news-agent.mjs ──► docs/news.json        ──► GitHub Pages ──► блок T123
            (сеть, фильтр, темы)      docs/news-report.json                       (только чтение)
```

Тильда — статический конструктор, своего бэкенда у неё нет, поэтому логика живёт в Actions, а в блоке остаётся тонкий клиент без ключей и секретов.

## Что внутри

```
.
├─ scripts/
│  ├─ news-agent.mjs      сборка дайджеста (Node 18+, без зависимостей)
│  ├─ health-check.mjs    проверка источников: HTTP, мс, записей, ошибка
│  ├─ test-parser.mjs     29 офлайн-тестов парсера и фильтра
│  └─ report-summary.mjs  markdown-сводка прогона для GitHub Actions
├─ docs/                  ← это и есть артефакт Pages
│  ├─ news.json           данные для блока (контракт не менялся)
│  ├─ news-report.json    статус источников для бейджа «источников 24/28»
│  ├─ index.html          служебная страница просмотра JSON
│  └─ .nojekyll
├─ snippets/tilda-t123.html   готовый блок для вставки в Tilda
└─ .github/workflows/news-agent.yml
```

## Быстрый старт

1. Скопируйте `scripts/`, `docs/`, `.github/`, `snippets/`, `package.json` в корень своего репозитория (уровни должны совпадать: workflow лежит в `.github/workflows/`).
2. Проверьте источники со своей машины:
   ```bash
   node scripts/health-check.mjs
   ```
3. Соберите дайджест локально:
   ```bash
   node scripts/news-agent.mjs
   ```
   Появится `docs/news.json` — откройте, проверьте заголовки.
4. В репозитории: **Settings → Pages → Source: GitHub Actions** (не «Deploy from a branch»).
5. **Actions → News digest → Run workflow**. Через минуту файлы будут доступны по адресу
   `https://<user>.github.io/<repo>/news.json`.
6. В Тильде вставьте блок T123 и замените `data-src` на этот URL (см. ниже).

Зависимостей нет: `npm install` не нужен. `npm`-скрипты — просто короткие алиасы, можно запускать `node` напрямую.

## Команды

```bash
node scripts/news-agent.mjs                 # сборка в docs/
node scripts/news-agent.mjs --days=7 --max=40 --out=docs
node scripts/news-agent.mjs --no-translate  # без DeepL, даже если ключ задан
node scripts/health-check.mjs               # все источники
node scripts/health-check.mjs --only=ru     # только российские
node scripts/health-check.mjs --strict      # exit 1, если кто-то не ответил
node scripts/health-check.mjs --json=docs/health.json
node scripts/test-parser.mjs                # офлайн-тесты, без сети
```

`node scripts/news-agent.mjs` возвращает `exit 1`, если в ленту не попало ни одной карточки: в CI это красит прогон, зато старый `news.json` не затирается пустым файлом.

| --- | --- |
| РФ | РБК, Ведомости, Ведомости Финансы, Коммерсантъ, Коммерсантъ Деньги, ТАСС, Интерфакс, BFM, Финам, Финмаркет, Banki.ru, Банк России, Smart-Lab, Российская газета, РИА Новости, Лента.ру |

Что было сделано с исходным списком: `rssexport.rbc.ru/news/20` отдаёт 404 (заменён на `/30`), лента Reuters Agency закрыта и отдаёт 404, `finance.yahoo.com/news/rssindex` — 404, `aif.ru/rss/all.xml` отдаёт RSS с текстом «error», `fomag.ru`, `dohod.ru`, `24.kz` — 404, `1prime.ru` и `forbes.ru` — HTML вместо фида. Вместо них добавлены Интерфакс, Банк России, Banki.ru, Smart-Lab, FT Markets, The Economist, Federal Reserve, Al Jazeera.

`health-check` — обязательный шаг перед тем, как доверять источнику:

```
ID            REGION OK  HTTP     MS ITEMS  NOTE
vedomosti     ru     OK   200    322    80  Ведомости
...
Итог: 28/28 источников ответили, 1234 записей, медиана 300 мс.
```

Если источник регулярно падает только с зарубежного IP (частая история у российских сайтов на раннере GitHub), уберите его или оставьте — агент продолжит работать на остальных, а в `news-report.json` будет честный статус.

## Формат данных

Контракт прежний — блок на Тильде менять не нужно.

```json
{
  "updated": "2026-11-24T10:20:14.394Z",
  "period": { "from": "24.11", "to": "24.11" },
  "news": [
    {
      "date":   { "ru": "24.11", "en": "Nov 24" },
      "region": "ru",
      "tag":    { "ru": "МАКРО", "en": "MACRO" },
      "source": { "ru": "Ведомости", "en": "Ведомости" },
      "title":  { "ru": "…", "en": "…" },
      "url":    "https://…"
    }
  ]
}
```

`news-report.json`: `updated`, `ok`, `degraded` (упало больше 40% источников), массив `sources` (`id`, `name`, `ok`, `status`, `ms`, `count`, `error`) и `stats` (`sources`, `sourcesOk`, `raw`, `relevant`, `written`, `byRegion`).

Без `TRANSLATE_API_KEY` поля `en` дублируют `ru` (и наоборот) — блок просто покажет один и тот же текст.

## Публикация на Pages

`docs/` уезжает артефактом (`actions/upload-pages-artifact` + `actions/deploy-pages`), поэтому папку выбирать не нужно.

Важно: старый деплой «из ветки» умеет только `/ (root)` и `/docs` — папку `/public` GitHub Pages не поддерживает. Отсюда и `docs/` вместо `public/`.

Проверка после первого прогона:

```bash
curl -I https://<user>.github.io/<repo>/news.json
# ждём: HTTP/2 200, content-type: application/json, access-control-allow-origin: *
```

CDN Pages кеширует файлы ~10 минут — это не баг, а нормально для раз в сутки.

## Вставка в T123

1. Откройте страницу в редакторе Тильды → **Библиотека блоков → Другое → HTML-код (T123)** (в старых аккаунтах — «T123»).
2. Вставьте содержимое `snippets/tilda-t123.html`.
3. Замените `data-src="https://USER.github.io/REPO/news.json"` на свой абсолютный URL.
4. При необходимости: `data-lang="en"` (английские поля) и `data-limit="20"`.
5. Сохраните и опубликуйте страницу.

```html
<div class="lp-digest" data-src="https://USER.github.io/REPO/news.json" data-lang="ru" data-limit="60">
  <div class="lp-digest__bar">
    <div class="lp-digest__title">Инвест-дайджест</div>
    <div class="lp-digest__status">Загрузка…</div>
  </div>
  <div class="lp-digest__grid"></div>
</div>
```

Что уже сделано в сниппете:

- **кеш-бастинг** — `?v=` меняется каждые 5 минут, иначе браузер и CDN держат старую ленту;
- **localStorage** (`lp_digest_v27`) — если Pages недоступен, показывается прошлый снимок, а не пустой блок;
- **status-бейдж** — «обновлено 24.11 · источников 27/28» из `news-report.json`;
- **стили в `<style>`** с префиксом `lp-`, чтобы не задеть тему Тильды; на мобильных одна колонка.

Если у вас уже стоит блок версии `53666221` (с кешем `lp_digest_v26` и встроенным fallback):

- достаточно поменять `data-fallback-url` на абсолютный URL нового `news.json` — контракт совпадает;
- если вставляете новый сниппет рядом, поднимите ключ кеша (в сниппете `v27`), иначе старый блок продолжит показывать своё;
- относительный `/news.json` на домене Тильды не найдётся никогда — только абсолютный URL на Pages/CDN.

## Настройки

| Что | Где | По умолчанию |
| --- | --- | --- |
| Окно свежести | `FRESH_DAYS` / `--days` | 14 дней |
| Размер ленты | `MAX_ITEMS` / `--max` | 60 карточек |
| Карточек с одного источника | `PER_SOURCE_CAP` | 5 |
| Доля мировой повестки | `WORLD_SHARE` | 0.3 |
| Перевод | `TRANSLATE_API_KEY` (DeepL) | выключен |
| Порог дедупликации | `similar()` в `news-agent.mjs` | Жаккар ≥ 0.72 |

**Перевод.** Ключ добавляется в **Settings → Secrets and variables → Actions → New repository secret**. Бесплатный тариф DeepL — 500 тыс. знаков в месяц; ключ заканчивается на `:fx`, эндпоинт `api-free.deepl.com` выбирается автоматически. Заголовки переводятся батчами по 40, ошибка перевода не роняет прогон.

**Темы.** `TOPICS` — 26 пар «тег → ключи». Русские ключи — основы слов без окончаний (`инфляц`, `ставк`, `дивиденд`), совпадение ищется с **начала слова**: «поставка» не считается «ставкой», «вакцинация» — «акцией». Латинские ключи проверяются по границам слов, чтобы `ai` не ловил `said`. Эти же ключи работают фильтром: карточка попадает в ленту, только если тема определяется по заголовку.

**Фильтр шума.** `INCIDENTS` (происшествия: `погиб`, `взрыв`, `атака`, `дрон`, `всу`…) и `NOISE_PREFIXES` (`обзор`, `погода`…) отсекают хоккей, криминал и светскую хронику, которые цепляют ключи «газ» или «банк». Проверка — `node scripts/test-parser.mjs`, там же кейсы вроде «Сбер отчитался за 9 месяцев» против «ВТБ отчитался за 9 месяцев» (не дубль).

## Ограничения, о которых стоит знать

- **cron в GitHub Actions неточный**: запуск в 09:30 МСК может стартовать в 09:45, а после 60 дней без активности в репозитории расписание отключается. Лечится ручным `Run workflow` раз в пару месяцев или внешним планировщиком, который дергает `workflow_dispatch`.
- **Российские источники с зарубежного IP** иногда отвечают 403. Прогон не падает, но такие ленты надо либо принять, либо заменить — `health-check` покажет.
- **Фильтр по ключам не идеален**: несколько карточек из 60 может оказаться не по теме (например, региональная новость со словом «регион»). Правится в `TOPICS`/`INCIDENTS`, без изменения блока.
- **Одна новость из четырёх изданий** может остаться четырьмя карточками: порог дедупликации сознательно консервативный (0.72 по Жаккару), потому что снижение до 0.4 начинает склеивать «Nvidia выросла» и «Nvidia упала». Если дублей слишком много — снижайте `PER_SOURCE_CAP` или ужесточайте порог.
- **Все карточки за один день** — нормально: ленты отдают последние 6–24 часа. `period` покажет фактический диапазон.

## Если что-то не работает

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Блок пустой, «данные недоступны» | неверный `data-src` или Pages ещё не задеплоен | открыть URL в браузере, проверить `curl -I` |
| В ленте старые новости | кеш CDN/браузера | проверить `?v=`, поднять `lp_digest_v27` → `v28` |
| Прогон красный, «0 карточек» | все источники упали или фильтр всё отсёк | `node scripts/health-check.mjs`, затем `--days=30` |
| `HTML вместо фида` | антибот на стороне источника | заменить источник |
| Кракозябры в тексте | фид в windows-1251 без charset | уже обрабатывается; если нет — пришлите URL фида |
| Pages отдаёт 404 на `news.json` | Pages не переключён на GitHub Actions | Settings → Pages → Source: GitHub Actions |
